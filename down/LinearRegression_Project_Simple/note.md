# 我这次学到了什么

## 一、这个项目在做什么

数据是 100 个学生的“学习时长”和“考试成绩”，我想找出一条直线，让这条线尽量贴近这些点，
这样以后给出一个学习时长，就能大概猜出成绩。

直线写成 `y = w * x + b`，w 是斜率、b 是截距，**训练模型就是找出最好的 w 和 b**。

怎么判断好不好？用均方误差 MSE：每条数据的预测值和真实值差多少，平方，再求平均。
数字越小说明直线越贴近数据。

怎么找到最好的 w 和 b？用梯度下降：看往哪个方向调参数能让 loss 变小，就往那个方向走一小步，反复走。

想清楚这三件事之后，代码其实就只是把这三件事翻译成 Python。

## 二、写代码的顺序

我没有一次把整个项目写完，而是分成了四步：

1. **先把数据读进来。** 写了 `dataset.py`，用 Python 自带的 csv 模块读文件。
   第一行是表头，要先用 `next(reader)` 读掉，不然 `float("hours")` 会报错。

2. **再把数学写出来。** 写了 `model.py`，里面是三个公式：怎么算预测值、怎么算 loss、怎么算梯度。
   **梯度是自己推的**：
   ```
   L = (1/n) * 求和 (y_hat - y)^2
   dL/dw = (2/n) * 求和 (y_hat - y) * x
   dL/db = (2/n) * 求和 (y_hat - y)
   ```
   推的时候用链式法则。写成代码的时候我把求和改成了矩阵乘法（`x.T @ diff`），
   因为用 for 循环写又慢又长，矩阵乘法一行就和公式长得一样。

3. **然后写训练循环。** 就是“算预测 → 算梯度 → 更新参数”循环很多次，只有一个循环，很好写。

4. **最后做对比实验。** 换不同的学习率、不同的批量大小各跑一遍，看结果有什么不同。

## 三、我踩过的两个坑

### 坑 1：不做标准化，loss 直接变成 nan

一开始我直接拿原始的 hours 和 score 训练，学习率取 0.1，结果 loss 很快就变成了 nan。
我第一反应是梯度推错了，就用数值微分检查了一遍梯度：

```
dL/dw 用公式算是 -21.4，用 (L(w+eps) - L(w-eps)) / (2*eps) 算也是 -21.4
```

说明梯度没问题。那问题出在哪？我去看了一下两个数的范围：
hours 是 1 到 10，score 是 30 到 100。

想明白了：**w 和 b 要走的“距离”差太多了。**
如果把 loss 的等高线画出来，它是一个特别扁的椭圆，
w 方向很“陡”、b 方向很“缓”。学习率如果按陡的方向来定，缓的方向就走得极慢；
按缓的方向来定，陡的方向一步就冲出去了。所以怎么调都不对。

解决办法是先把 x 变成“平均值 0、标准差 1”：`x = (x - mean) / std`。
这样两个方向的尺度接近了，梯度下降就能顺着走下去。做完之后，lr 从 0.05 到 0.9 都稳定收敛。

**这个坑让我明白：机器学习里“数据长什么样”有时候比“算法怎么写”更重要。**

### 坑 2：图被一个特别大的数毁掉了

画“不同学习率对比”这张图的时候，图完全不能看：
lr = 1.2 的时候 loss 涨到了 1e62，这一个点把纵轴撑到了 1e62，
其他几条正常的曲线全被压成贴着横轴的一条直线，什么都看不出来。

我一开始以为是自己代码写错了，后来才明白这不是 bug，**是我本来就想看到的现象**：
学习率太大就是会发散。问题只在于它把图毁了。

我试过把纵轴改成对数坐标，但 1e62 和 20 差得实在太多，还是看不清。
最后只能在画图的时候把 lr = 1.2 这条线去掉，但把它的结果保留在控制台的打印里和报告的表格里。
**这个问题我觉得没有真正解决**，只是绕过去了。

## 四、几个实验结论

1. **闭式解可以用来检查梯度下降对不对。**
   一个特征的时候有精确公式，我算出来是 `y = 6.1154 * x + 33.3054`，
   梯度下降跑出来是 `y = 6.1154 * x + 33.3054`，几乎完全一样。
   这让我对自己的实现放心了。

2. **学习率太小和太大都不行。**
   - lr = 0.001：200 轮之后 loss 还有 1945，离最低点 24.98 差得远，就是走得太慢；
   - lr = 0.05 ~ 0.9：都能收敛到 24.98；
   - lr = 1.2：直接涨到 1e62 然后变成 inf。
   所以学习率不能随便填，得试。

3. **批量大小是在“梯度准”和“更新次数多”之间做取舍。**
   - 每批 100 个：一个 epoch 只更新 1 次，但梯度最准，最后 loss 最低（24.9786）；
   - 每批 16 个：更新 6 次，结果 25.0070；
   - 每批 1 个：一个 epoch 更新 100 次，但最后 loss 最差（28.7995）。
   我一开始以为“更新次数多 = 学得好”，结果不是。
   每批 1 个的时候梯度只由一个样本决定，方向很偏，
   走到最低点附近之后还会被单个样本带着来回跳，所以最后停的地方反而不是最好的点。

4. **测试集的结果和训练集很接近**（loss 24.98 对 20.17，测试 R2 = 0.9328），
   说明模型没有过拟合，而且它学到的东西确实能推广到没见过的新数据上。

## 六、一点感想

以前我觉得线性回归特别简单，不就是一条直线吗。
自己从零写一遍才发现，真正难的不是公式，而是这些“参数到底该填多少”的问题：
学习率填多少、要不要标准化、每批取多少个样本……
这些问题没有标准答案，**只能自己跑实验、看结果、再想办法解释为什么**。

这个项目里每一行代码我都写了注释，因为我知道过几天自己就会忘了当时为什么这么写。
